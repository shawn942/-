
# 搜尋演算法實作作業

## 一、作業目的

本作業使用 Python 實作五種搜尋問題：

1. 老鼠走迷宮（DFS）
2. 狼羊甘藍菜過河（BFS）

## 三、演算法說明

### 1. 老鼠走迷宮（DFS）

DFS（Depth-First Search）稱為深度優先搜尋。

演算法會從起點開始，選擇一個方向持續探索。
如果遇到牆壁、已走過的位置或死路，
就進行回溯，尋找其他可以前進的方向。

實作步驟：

1. 建立迷宮地圖。
2. 設定老鼠起點 S 與出口 G。
3. 使用 DFS 搜尋上下左右四個方向。
4. 記錄走訪過的位置，避免重複搜尋。
5. 找到出口後輸出路徑。

優點：
- 程式容易理解。
- 適合尋找可行路徑。
- 可以搭配遞迴與回溯法。

缺點：
- 不保證找到最短路徑。

時間複雜度：O(V + E)

執行結果：
成功找到迷宮出口。
範例地圖的最短路徑長度為 11 步。

### 2. 狼羊甘藍菜過河（BFS）

BFS（Breadth-First Search）稱為廣度優先搜尋。

問題條件：
- 農夫一次最多帶一個物品過河。
- 狼不能在沒有農夫時與羊單獨相處。
- 羊不能在沒有農夫時與甘藍菜單獨相處。
- 所有角色必須安全抵達對岸。

使用四個數字表示狀態：

(農夫, 狼, 羊, 甘藍菜)

0：左岸
1：右岸

起始狀態：(0,0,0,0)
目標狀態：(1,1,1,1)

演算法流程：

1. 將起始狀態加入佇列。
2. 產生所有可能的過河方式。
3. 排除違反條件的狀態。
4. 將合法且尚未搜尋的狀態加入佇列。
5. 搜尋到目標後還原路徑。

優點：
- 每次移動成本相同時，可以找到最少步數。
- 適合有限狀態空間的搜尋問題。

缺點：
- 狀態很多時會消耗較多記憶體。

時間複雜度：O(V + E)

執行結果：
最少需要 7 次渡河。

一組解法：

1. 農夫帶羊過河。
2. 農夫獨自回來。
3. 農夫帶狼過河。
4. 農夫帶羊回來。
5. 農夫帶甘藍菜過河。
6. 農夫獨自回來。
7. 農夫帶羊過河。

### 3. 八皇后問題（DFS + Backtracking）

八皇后問題是在 8×8 的棋盤上放置 8 個皇后。

規則：
- 皇后不能位於同一列。
- 皇后不能位於同一欄。
- 皇后不能位於同一條對角線。

使用 DFS 逐列放置皇后。

當某個位置與已放置的皇后衝突時，
立即放棄該位置並進行回溯。

演算法流程：

1. 從第一列開始搜尋。
2. 嘗試每一個欄位。
3. 檢查欄位及對角線是否衝突。
4. 如果合法，就放置皇后並進入下一列。
5. 如果無法繼續，回溯上一列。
6. 完成八列後儲存解答。

優點：
- 可以列舉所有解。
- 能透過剪枝減少搜尋次數。

缺點：
- 棋盤越大，搜尋時間可能快速增加。

時間複雜度上界：O(N!)

執行結果：
八皇后共有 92 組不同解。

### 4. NPC 搜尋玩家（A*）

A* 是結合實際成本與預估距離的啟發式搜尋演算法。

使用公式：

f(n) = g(n) + h(n)

其中：

g(n)：起點到目前位置的成本。
h(n)：目前位置到玩家的預估距離。
f(n)：搜尋節點的估計總成本。

本作業使用曼哈頓距離：

h(n) = |x1-x2| + |y1-y2|

演算法流程：

1. 設定 NPC 為起點 S。
2. 設定玩家為目標 G。
3. 計算每個候選位置的 f 值。
4. 優先搜尋 f 值較小的位置。
5. 避開地圖中的障礙物。
6. 找到玩家後還原移動路徑。

優點：
- 適合遊戲角色尋路。
- 可以使用啟發式函數提高搜尋效率。
- 使用合適的啟發式時可保證最短路徑。

缺點：
- 需要設計適當的啟發式函數。
- 動態障礙可能需要重新規劃路線。

執行結果：
NPC 成功找到玩家。
範例地圖最短路徑為 14 步。

### 5. IC 設計電路繞線

IC 電路繞線的目的，是在不穿越障礙物的條件下，
尋找兩個接點之間的可行線路。

本作業採用二維網格進行模擬。

S：電路起點
T：電路終點
#：障礙物
.：可繞線區域

實作六種搜尋方法：

#### 方法一：Lee Algorithm（BFS）

使用 BFS 由起點逐層向外搜尋。

特點：
- 能找到最短線長。
- 實作容易。
- 大型網格可能需要較多記憶體。

#### 方法二：雙向 BFS

從起點和終點同時進行廣度搜尋，
直到兩個搜尋範圍相遇。

特點：
- 保證最短線長。
- 在部分地圖可減少搜尋範圍。

#### 方法三：DFS 回溯

沿著一個方向持續探索，
遇到死路後回溯。

特點：
- 容易實作。
- 可以找到可行路線。
- 不保證最短線長。

#### 方法四：Dijkstra

每次選擇目前累積成本最低的節點。

本作業成本設定：

總成本 = 線長 + 2 × 轉彎次數

特點：
- 可以處理非負的加權成本。
- 能找到最低成本路徑。

#### 方法五：A*

使用實際成本與啟發式估計：

f(n) = g(n) + h(n)

其中 h(n) 使用曼哈頓距離。

特點：
- 可以朝目標方向引導搜尋。
- 在本作業設定下能找到最低加權成本。

#### 方法六：Hadlock Algorithm

利用曼哈頓距離判斷移動方向。

當移動使距離終點變遠時，
視為一次繞路（Detour）。

透過減少繞路次數來尋找最短路徑。

特點：
- 適用於正交網格的繞線問題。
- 在本作業設定下可找到最短線長。

執行結果：

Lee BFS：16 格
雙向 BFS：16 格
DFS 回溯：16 格
Dijkstra：16 格
A*：16 格
Hadlock：16 格

注意：以上是此範例地圖的結果。
不同地圖下，DFS 不一定能找到最短路線。

本作業還會計算每條路徑的轉彎次數，
用來比較不同演算法的繞線品質。

## 四、IC 繞線方法比較

| 方法 | 保證最短線長 | 支援加權成本 |
| --- | --- | --- |
| Lee BFS | 是 | 否 |
| 雙向 BFS | 是 | 否 |
| DFS | 否 | 否 |
| Dijkstra | 不一定 | 是 |
| A* | 不一定 | 是 |
| Hadlock | 是 | 否 |

Dijkstra 與 A* 在本作業會最佳化
「線長 + 轉彎懲罰」，
因此不一定選擇步數最少的路徑。

真實 IC 設計還需要考慮：

- 金屬層數與通孔
- 線寬與線距
- 電阻與寄生電容
- 訊號延遲
- 多條線路的擁塞問題
- 設計規則檢查（DRC）

因此本程式是教學用的簡化繞線模型。

## 五、心得與結論

透過這次實作，我了解不同搜尋演算法
適合解決不同類型的問題。

DFS 適合尋找可行解，也可以搭配回溯法
解決八皇后等組合問題。

BFS 適合每一步成本相同、
需要尋找最少步數的問題。

A* 可以利用啟發式函數，
更有效率地搜尋指定目標。

在 IC 電路繞線中，
除了尋找可行路徑，
還必須考慮線長與轉彎成本。

因此，選擇演算法時，
需要根據問題的目標與限制，
決定最適合的搜尋方式。
