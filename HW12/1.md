# 本週計算理論：從希爾伯特到庫克

這週的內容是 ccc 老師的 `_book`。全書在回答兩個問題：

1. **電腦能不能解決所有問題？** 答案是不能。第 1～5 章講可計算性。
2. **能解的問題，要算多久？** 第 6 章講計算複雜度，也就是 P 和 NP。

| 年代 | 人物 | 做了什麼 |
|---|---|---|
| 1900 | 希爾伯特 | 問：數學能不能全部形式化，讓機器自動證明所有真命題？ |
| 1931 | 哥德爾 | 證明含算術的系統裡，一定有證不出來的真命題 |
| 1936 | 丘奇 | 發明 λ 演算，證明「兩個函數是否等價」無法判定 |
| 1936 | 圖靈 | 發明圖靈機，證明停機問題無法判定 |
| 1956 | 喬姆斯基 | 把文法分成四級，每一級剛好對應一種機器 |
| 1971 | 庫克 | 證明 SAT 是 NP-Complete，提出 P vs NP 問題 |

## 第 1 章：希爾伯特的問題

**重點：** 證明可以看成「用推論規則一步步改寫符號」，而這件事可以交給機器做。

書中的 `inference.py` 是前向推論引擎，只用一條規則 Modus Ponens（肯定前件）：知道 P，又知道 P ⇒ Q，就推出 Q。

```
事實：A, B
規則：A⇒E, B⇒F, E&F⇒H
推論：A → E，B → F，E&F → H ✓
```

`animal.kb` 是同樣的做法：輸入「會飛、生蛋、長腿」，先推出「鳥類」，再推出「鴕鳥」。這其實就是早期 AI 的專家系統。

希爾伯特計畫要求數學系統同時做到這幾點：
- **完備性**：所有真命題都能被證明
- **一致性**：不會推出矛盾
- **可判定性**：有一個演算法能判斷任何命題的真假

後面幾章其實都在說明這個夢想為什麼做不到。

## 第 2 章：哥德爾的定理

**羅素悖論**：定義 A = {x | x ∉ x}，問 A ∈ A 嗎？假設是，依定義就不是；假設不是，依定義就是。通俗版是理髮師悖論：「我只幫不自己剪頭髮的人剪頭髮」，那理髮師要不要幫自己剪？結果是集合論改用 ZFC 公理重建。

**皮亞諾公理**用「0」和「後繼者 S(x)」定義自然數的加法和乘法，例如 x + S(y) = S(x + y)。第 3 章的 Church 數就是同樣的想法。

**不完備定理的核心**：哥德爾把公式和證明都編成數字（哥德爾編碼），所以算術系統可以談論它自己的證明。接著他構造出一句話 G：

> G =「G 無法被證明」

- 如果 G 能被證明，G 說的就是假的，系統證明了假命題，也就不一致。
- 如果 G 不能被證明，G 說的就是真的。於是存在**真但證不出來**的命題。

所以只要系統是一致的，它就不完備。這和理髮師悖論、停機問題用的是同一招：**自我指涉 + 反證法**。

> ⚠️ 書裡說「ZFC 是完備的，加了皮亞諾公理才不完備」，這個說法不精確，考試時建議用以下版本：
> - **完備定理（1929）**講的是一階邏輯這套推論方法：在所有模型裡都成立的公式，都能被證明。
> - **不完備定理（1931）**講的是理論：任何一致、能表達基本算術的理論，都有無法證明也無法否證的命題。ZFC 本身就能表達算術，所以 ZFC 自己就不完備。
>
> 兩個定理的「完備」意思不同，所以並不矛盾。

## 第 3 章：丘奇的函數（λ 演算）

λ 演算只有三種東西：變數 `x`、函數定義 `λx.M`、函數呼叫 `(M N)`。計算的方式是 **β 歸約**，也就是把參數代進去：`(λx.M) N → M[x:=N]`。

這一章最驚人的地方，是**完全沒有資料型態，只靠函數就能做出所有東西**：

```python
TRUE  = lambda t: lambda f: t      # 兩個選一個，選第一個
FALSE = lambda t: lambda f: f      # 選第二個
IF    = lambda c: lambda t: lambda f: c(t)(f)   # 布林值本身就會「選」
```

**Church 數**：數字 n 的意思是「把 f 套用 n 次」。
- 0 = λf.λx.x（f 用 0 次）
- 2 = λf.λx.f(f(x))
- SUCCESSOR 就是再多套用一次 f。這和皮亞諾公理的 S(x) 是同一個概念。

**Y-Combinator**：λ 函數沒有名字，沒辦法呼叫自己，Y 就是用來做遞迴的。它滿足 `Y(g) = g(Y(g))`，所以 g 會拿到「自己」當參數。

```python
Y = lambda f: (lambda x: f(lambda y: x(x)(y)))(lambda x: f(lambda y: x(x)(y)))
FACTORIAL = Y(lambda f: lambda n: IF(IS_ZERO(n))(...)(... f(PREDECESSOR(n)) ...))
```

（書上的寫法多包了一層 `lambda y: ...(y)`。這是因為 Python 會先算參數，原版 Y 會無限展開，所以要延遲計算。這種版本嚴格來說叫 Z-combinator。）

**丘奇的不可解定理**：沒有任何程式能判斷兩個 λ 式子是否等價。直覺的理由是，要比較兩個函數的結果就得把它們跑完，但你不知道它們會不會停。

## 第 4 章：圖靈的機器

**有限狀態機（FSM）**：只有狀態，沒有其他記憶，看一個字元就轉移一次。範例 `even0.py` 判斷 0 的個數是不是偶數：

```
s1 讀到 0 → s2，s2 讀到 0 → s1，讀到 1 都不動；s1 是接受狀態
```

**圖靈機 = 有限狀態機 + 可讀寫、可左右移動的無限長磁帶**。轉移規則寫成 `'狀態,讀到的字' → '新狀態,寫入的字,移動方向'`。

`anbncn.py` 示範圖靈機能辨識 aⁿbⁿcⁿ，有限狀態機做不到。做法是來回掃描，每一輪各劃掉一個 a、一個 b、一個 c，全部劃完就接受。

**停機問題（必考）**：假設存在 `isHalt(code, data)` 能判斷程式會不會停，就能寫出：

```python
def U(code):
    if isHalt(code, code): while True: pass   # 判斷會停，就故意不停
    else: exit()                               # 判斷不停，就故意停
```

問 `U(U)` 會不會停？isHalt 答「會停」，U 就不停；答「不停」，U 就停。兩邊都錯，所以 isHalt 不存在。

為什麼不能直接跑跑看？`halt.py` 示範了原因：`f2(1000)` 要跑 1000⁴ 步，你等不到結果時，無法分辨它是跑很久還是永遠不會停。

## 第 5 章：喬姆斯基的語法

文法就是一組改寫規則，從 S 開始不斷替換，直到全部變成小寫的終結符號。`grammar.py` 每次隨機選一條規則展開。注意它和第 1 章的推論引擎、第 4 章的狀態機是同一種模式：**找到左式，換成右式**。

**喬姆斯基階層（必背）**：

| 型 | 語言 | 規則形式 | 對應機器 | 範例 |
|---|---|---|---|---|
| 3 | 正規語言 | A → a 或 A → aB | 有限狀態機（正規表達式） | aⁿbᵐ |
| 2 | 上下文無關 | A → γ | 下推自動機（FSM + 堆疊） | aⁿbⁿ |
| 1 | 上下文相關 | αAβ → αγβ | 線性有界自動機 | aⁿbⁿcⁿ |
| 0 | 遞歸可枚舉 | α → β | 圖靈機 | — |

每往上一級，能力就嚴格變強。
- **aⁿbⁿ** 要「記住有幾個 a」，FSM 的狀態數量有限，記不住，需要堆疊。規則是 `S → a S b | a b`。
- **aⁿbⁿcⁿ** 要同時比對三組，一個堆疊不夠，規則必須看上下文。例如 `C B → … → B C` 一連串規則，用來把 B 和 C 交換到正確位置。

實務上，lexer 用的正規表達式是第 3 型，程式語言的語法（BNF）是第 2 型。這就是編譯器分成兩個階段的理論基礎。

**Church–Turing 論題**：凡是直覺上「可以計算」的問題，圖靈機都能計算。λ 演算和圖靈機能力相同，這一點是已被證明的定理。但「可計算就等於圖靈機能算」是一個**論題**，沒辦法證明，因為「直覺上可計算」不是數學定義。

## 第 6 章：庫克的證明（P vs NP）

這章的問題從「能不能算」變成「要算多久」。

- **P**：一般（確定型）圖靈機能在多項式時間內**解出**答案的問題。
- **NP**：非確定型圖靈機能在多項式時間內解出的問題。可以想成機器遇到分岔時，每條路同時往下跑。等價的說法是：給你一個答案，你能在多項式時間內**驗證**它對不對。
- **P = NP？** 至今沒有人解決。

**SAT 問題**：一個布林式有沒有某組變數值能讓它為真？
- 要**找**答案，暴力法得試 2ⁿ 種組合（`sat.py`），1024 個變數就要試 2¹⁰²⁴ 次，永遠跑不完。
- 要**驗證**答案，只要把值代進去算一次（`expEval.py`），一下就好。
- 「難找、好驗證」就是 NP 問題的典型特徵。

**歸約**：把 A 問題的輸入轉成 B 問題的輸入，用 B 的演算法解，再把答案轉回來。

```python
def a(ia): return b2a(b(a2b(ia)))
```

書中範例是把八皇后轉成整數規劃（`queen8.py`）：每格一個 0/1 變數，限制每行、每列、每條斜線最多一個皇后，然後交給 `mip` 求解。

**庫克定理**：所有 NP 問題都能在多項式時間內歸約成 SAT，所以 SAT 是 **NP-Complete**。之後 Karp 又證明了另外 21 個問題（TSP、背包問題等）也是 NP-Complete。只要其中任何一個能在多項式時間內解出，P 就等於 NP。
