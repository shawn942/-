填表完成後，從右下角 dp[N][M] 往左上角回溯（Backtracking）：若遇到左上角轉移代表內容相同（保留）；往上走代表刪除 A 的行；往左走代表新增 B 的行。
時間複雜度：O(N×M)。無論兩個檔案有多相似（哪怕一模一樣），都必須把整張二維表格填滿。
空間複雜度：O(N×M)。需要完整保留二維表格以供回溯輸出差異步驟。
🔹 非動態規劃解法：Myers Diff 演算法 (圖論最短路徑搜尋)
運作原理：
Myers 將比對問題轉化為在 (N×M) 網格圖上的最短路徑搜尋問題。從座標 (0,0) 出發前往 (N,M)：
往右走一步 (x+1,y) 代表刪除 A[x]（代價為 1）。
往下走一步 (x,y+1) 代表新增 B[y]（代價為 1）。
若 A[x]=B[y]，可以沿著對角線 (x+1,y+1) 免費滑行（代價為 0，稱為 Snake）。
演算法以編輯步數 d=0,1,2,…,D 為外層迴圈（類似 BFS 廣度優先搜尋），只記錄每條對角線 k=x−y 上能走到的最遠 x 座標。一旦觸及終點 (N,M) 立即停止搜尋。
時間複雜度：O((N+M)D)，其中 D 為兩個檔案實際相差的行數（最小編輯距離）。在程式碼日常修改中，D 通常極小，因此實際運行速度接近線性 O(N+M)。

from typing import List, Dict

# =====================================================================
# 解法一：動態規劃 (LCS Bottom-Up 逐步建表法)
# =====================================================================
def lcs_dp_diff(a: List[str], b: List[str]) -> List[str]:
    n, m = len(a), len(b)
    # 1. 建立 (n+1) x (m+1) 的表格並初始化為 0
    dp = [[0] * (m + 1) for _ in range(n + 1)]

    # 2. 逐步建表：由前面的結果推算後面的結果
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])

    # 3. 從表格右下角回溯 (Backtrack) 產生 Diff 結果
    diff_result = []
    i, j = n, m
    while i > 0 or j > 0:
        if i > 0 and j > 0 and a[i - 1] == b[j - 1]:
            diff_result.append(f"  {a[i - 1]}")
            i -= 1
            j -= 1
        elif j > 0 and (i == 0 or dp[i][j - 1] >= dp[i - 1][j]):
            diff_result.append(f"+ {b[j - 1]}")
            j -= 1
        else:
            diff_result.append(f"- {a[i - 1]}")
            i -= 1

    return diff_result[::-1]


# =====================================================================
# 解法二：非動態規劃 (Myers 圖論對角線搜尋演算法)
# =====================================================================
def myers_diff(a: List[str], b: List[str]) -> List[str]:
    n, m = len(a), len(b)
    max_d = n + m
    v: Dict[int, int] = {1: 0}
    trace: List[Dict[int, int]] = []

    for d in range(max_d + 1):
        trace.append(v.copy())
        for k in range(-d, d + 1, 2):
            # 決定從上方 (新增) 還是左方 (刪除) 走過來
            if k == -d or (k != d and v.get(k - 1, -1) < v.get(k + 1, -1)):
                x = v.get(k + 1, 0)
            else:
                x = v.get(k - 1, 0) + 1
            y = x - k

            # 對角線免費滑行 (Snake)：內容相同就一路往下右滑
            while x < n and y < m and a[x] == b[y]:
                x += 1
                y += 1

            v[k] = x
            if x >= n and y >= m:
                return _backtrack_myers(trace, a, b, d)
    return []

def _backtrack_myers(trace: List[Dict[int, int]], a: List[str], b: List[str], d: int) -> List[str]:
    diff_result = []
    x, y = len(a), len(b)
    for step in range(d, 0, -1):
        v = trace[step]
        k = x - y
        if k == -step or (k != step and v.get(k - 1, -1) < v.get(k + 1, -1)):
            prev_k = k + 1
        else:
            prev_k = k - 1
        prev_x = v[prev_k]
        prev_y = prev_x - prev_k

        while x > prev_x and y > prev_y:
            x -= 1
            y -= 1
            diff_result.append(f"  {a[x]}")
        if x > prev_x:
            x -= 1
            diff_result.append(f"- {a[x]}")
        elif y > prev_y:
            y -= 1
            diff_result.append(f"+ {b[y]}")

    while x > 0 and y > 0:
        x -= 1
        y -= 1
        diff_result.append(f"  {a[x]}")
    return diff_result[::-1]

主題二：blast — DNA 相似字串搜尋 (Smith-Waterman 動態規劃 v.s. Seed-and-Extend)
1. 問題背景與定義
在生物資訊學中，我們常需要在龐大的基因資料庫序列 DB（長度 M）中，搜尋與查詢序列 Query（長度 N）高度相似的「局部片段（Local Alignment）」。計分規則通常為：字元匹配得分（如 +2）、不匹配或缺失扣分（如 −1）。
2. 兩者原理解析
🔹 動態規劃解法：Smith-Waterman 演算法 (逐步建表法)
運作原理：
建立大小為 (N+1)×(M+1) 的二維表格 dp，其中 dp[i][j] 代表以 Query[i−1] 與 DB[j−1] 為結尾的最高局部比對得分。
關鍵機制（歸零重啟）：與全域比對不同，若某處累計分數變成負數，代表這段序列完全不相似，局部比對允許直接將分數歸零（max(0, ...)），重新起算一段新的局部匹配。
狀態轉移方程：

時間複雜度：O(N×M)。保證能找到數學上 100% 最高分的局部匹配，但當資料庫 M 高達數十億鹼基時，建表時間過長。
空間複雜度：O(N×M)。
🔹 非動態規劃解法：BLAST 種子與延伸演算法 (Seed-and-Extend 啟發式搜尋)
運作原理：
BLAST 觀察到「真正高度相似的 DNA 序列，必定包含一小段完全一模一樣的連續字元」。因此演算法捨棄了整張表格，改採兩階段啟發式策略：
播種（Seeding）：將資料庫序列切成固定長度為 k 的短字元片段（k-mer），建立雜湊表（Hash Table）索引。搜尋時直接以 O(1) 查表找出 Query 與 DB 完全相同的「種子命中點」。
雙向延伸與剪枝（Extend & X-Dropoff Pruning）：從種子位置同時向左、向右逐一比對字元並累加分數。一旦發現分數從歷史高點跌落超過設定閥值（dropoff），代表已經離開相似區域，立刻 break 停止延伸（停損剪枝），絕不浪費時間比對整條序列。
時間複雜度：平均時間複雜度接近 O(N+M)（視種子命中率而定），比動態規劃快上數十至數百倍。
空間複雜度：O(M)，主要用於儲存資料庫的 k-mer 雜湊索引表。
3. 演算法綜合比較
比較維度	動態規劃 (Smith-Waterman 演算法)	非動態規劃 (BLAST Seed-and-Extend)
核心思維	嚴謹填表，窮舉所有可能的局部起點與終點	雜湊表快速定位種子 + 雙向延伸停損剪枝
時間複雜度	O(N×M)	啟發式搜尋，實務上逼近線性 O(N+M)
準確度保證	100% 保證找到全域最佳解（數學最優）	啟發式近似解（若相似片段中無連續 k 個相同字元會漏抓）
搜尋範圍	必須掃描並填滿整個二維矩陣	只在有「種子命中」的極小區域周圍進行比對
實務應用場景	短序列精確比對、驗證關鍵基因變異	NCBI 全球基因庫搜尋引擎（數秒內比對數億筆序列）

from collections import defaultdict
from typing import Dict, Any

# =====================================================================
# 解法一：動態規劃 (Smith-Waterman 局部序列比對演算法)
# =====================================================================
def smith_waterman_dp(query: str, db: str, match: int = 2, mismatch: int = -1, gap: int = -1) -> Dict[str, Any]:
    n, m = len(query), len(db)
    # 1. 建立 (n+1) x (m+1) 的 DP 表格
    dp = [[0] * (m + 1) for _ in range(n + 1)]
    
    max_score = 0
    max_pos = (0, 0)

    # 2. 逐步建表：若分數小於 0 則直接歸零 (局部比對的核心)
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            score_diag = dp[i - 1][j - 1] + (match if query[i - 1] == db[j - 1] else mismatch)
            score_up   = dp[i - 1][j] + gap
            score_left = dp[i][j - 1] + gap
            
            dp[i][j] = max(0, score_diag, score_up, score_left)
            
            if dp[i][j] > max_score:
                max_score = dp[i][j]
                max_pos = (i, j)

    # 3. 從最高分位置往左上角回溯，直到遇到 0 為止
    i, j = max_pos
    q_end, db_end = i, j
    while i > 0 and j > 0 and dp[i][j] > 0:
        score_current = dp[i][j]
        score_diag = dp[i - 1][j - 1] + (match if query[i - 1] == db[j - 1] else mismatch)
        if score_current == score_diag:
            i -= 1
            j -= 1
        elif score_current == dp[i - 1][j] + gap:
            i -= 1
        else:
            j -= 1

    return {
        "score": max_score,
        "query_range": (i, q_end),
        "db_range": (j, db_end),
        "query_seq": query[i:q_end],
        "db_seq": db[j:db_end]
    }


# =====================================================================
# 解法二：非動態規劃 (BLAST Seed-and-Extend 種子與延伸演算法)
# =====================================================================
def mini_blast(query: str, db: str, k: int = 4, match: int = 2, mismatch: int = -1, dropoff: int = 3) -> Dict[str, Any]:
    # 1. 建立資料庫的 k-mer 雜湊索引 (Seeding)
    db_index = defaultdict(list)
    for i in range(len(db) - k + 1):
        db_index[db[i:i + k]].append(i)

    best_hit = {"score": -1}

    # 2. 掃描 Query 尋找種子命中點並進行雙向延伸 (Extension)
    for q_pos in range(len(query) - k + 1):
        kmer = query[q_pos:q_pos + k]
        for db_pos in db_index.get(kmer, []):
            # 向右與向左延伸，遇到分數跌落超過 dropoff 立即停損 (Pruning)
            max_s = k * match
            
            # 向右延伸
            curr_s = max_s
            q_r, db_r = q_pos + k, db_pos + k
            best_q_r, best_db_r = q_r, db_r
            while q_r < len(query) and db_r < len(db):
                curr_s += match if query[q_r] == db[db_r] else mismatch
                q_r += 1
                db_r += 1
                if curr_s > max_s:
                    max_s = curr_s
                    best_q_r, best_db_r = q_r, db_r
                elif max_s - curr_s >= dropoff:
                    break  # 停損剪枝！

            # 向左延伸
            curr_s = max_s
            q_l, db_l = q_pos, db_pos
            best_q_l, best_db_l = q_l, db_l
            while q_l > 0 and db_l > 0:
                curr_s += match if query[q_l - 1] == db[db_l - 1] else mismatch
                q_l -= 1
                db_l -= 1
                if curr_s > max_s:
                    max_s = curr_s
                    best_q_l, best_db_l = q_l, db_l
                elif max_s - curr_s >= dropoff:
                    break  # 停損剪枝！

            if max_s > best_hit["score"]:
                best_hit = {
                    "score": max_s,
                    "query_range": (best_q_l, best_q_r),
                    "db_range": (best_db_l, best_db_r),
                    "query_seq": query[best_q_l:best_q_r],
                    "db_seq": db[best_db_l:best_db_r]
                }

    return best_hit
